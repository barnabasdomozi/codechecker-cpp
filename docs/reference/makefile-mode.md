# Reference: `analyze --makefile`

Usage: [../usage/makefile-mode.md](../usage/makefile-mode.md)

Python source: `analyzer/codechecker_analyzer/makefile.py`, `analyzer.py`.

## When

After the checker configuration and metadata step of `perform_analysis`
([analyze.md](analyze.md) §4 step 9): the Makefile is written instead of
running pre-analysis and analysis. `analyze` then continues with its normal
epilogue (side files, metadata.json, compile_cmd.json). INFO lines:
`Creating Makefile from the analyzer commands: '<out>/Makefile'...` and
`Done.`

Pre-analysis targets are generated if the CTU collect phase is requested; CTU
data is also prepared when statistics are configured.

## Target names

```
analyzer_tag = analyzer name with '-' removed        (clangsa, clangtidy, cppcheck, gcc, infer)
target       = md5_hex( analyzer_tag + "_" + source + "_" + original_command )
```

## File layout

```
#
# Autogenerated by CodeChecker v<version>.
#
# DO NOT EDIT UNLESS YOU ARE SURE THAT YOU KNOW WHAT YOU ARE DOING.
#

export PATH := <CC_BIN_DIR>:<data dir>/python3/bin:${PATH}      (only if CC_DATA_FILES_DIR is set)
export LD_LIBRARY_PATH := <value>                              (each of these three only if set)
export PYTHONPATH := <value>
export PYTHONHOME := <value>

# Default target to run all analysis.
default: all

# Target to run only '<tag>' analysis.          (one block per analyzer, in analyzer order)
all: all_<tag>

[pre-analysis targets, per clangsa action]
<analysis targets, per action>
[post_pre_all_clangsa target]
```

Log prefix used in recipes: `` [`date +'%Y-%m-%d %H:%M:%S'`] - ``.

### Analysis target (every action)

```
<target>: [post_pre_all_clangsa]          (dependency only for clangsa actions when pre-analysis is on)
	@echo "<log prefix> <analyzer> analyze <source>."
	<command>
all_<tag>: <target>
```

`<command>`:
- clang-tidy:
  ```
  @<shell-quoted analyzer command> > <result_file>.output
  	@report-converter -t clang-tidy -o <out> --filename {source_file}_{analyzer}_<target> <result_file>.output 1>/dev/null
  	@rm -rf <result_file>.output
  ```
  (so clang-tidy result files are named with the **Makefile target hash**,
  not the action hash, and are only created when there are reports;
  `parse --status` therefore reports clang-tidy results as missing)
- all others: `@<shell-quoted analyzer command> 1>/dev/null`

The analyzer command is built exactly as in a normal run
([analyzer-drivers.md](analyzer-drivers.md) §5), including the result file
path. With statistics, the statistics checker config is always added for
clangsa actions that depend on pre-analysis.

### Pre-analysis targets (clangsa actions, CTU collect)

```
pre_<target>:
	@echo "<log prefix> Pre-analysis of <source>."
	@mkdir -p <ctu-dir>/<arch>/ast/<dir of source>
	@<AST dump command>
	@mkdir -p <ctu-dir>/<arch>/tmpExternalFnMaps
	@<mapping tool command> > <ctu-dir>/<arch>/tmpExternalFnMaps/<uuid4> 2>/dev/null
	@sed -E "s|/(.*)|ast/\1.ast|" <map file> > <map file>_tmp
	@mv -f <map file>_tmp <map file>
	[@mkdir -p <stat tmp dir>]                       (statistics)
	[@<stats collect command> > <stat tmp dir>/<basename><uuid4>.stat 2>&1]
pre_all_clangsa: pre_<target>
```

The triple arch is computed when the Makefile is written (runs Clang once per
action).

### Post-pre-analysis target

```
post_pre_all_clangsa: pre_all_clangsa
	@find <ctu-dir> -maxdepth 1 -mindepth 1 -type d -exec merge-clang-extdef-mappings -i {}/tmpExternalFnMaps -o {}/externalDefMap.txt \;
	@post-process-stats -i <stat tmp dir> <stats dir>         (statistics)
```

Recipes rely on `report-converter`, `merge-clang-extdef-mappings` and
`post-process-stats` being on `PATH` (provided by the exported `PATH`).
